Research log · The paper behind the play

Save the decision.
Then carry it forward.

Autopilot separates reasoning from execution: the model records executable actions and control flow, then a deterministic executor runs and checkpoints that plan.

Recovery restores the chosen plan and its progress. This preserves an already made decision; it does not guarantee that the decision was correct.

Five recovery strategies

AutopilotRestore the machine-executable plan and the executor's progress. In these experiments, no new model reasoning is required after the crash.

ReAct + agent stateRestore persisted agent state, then resume the model's reasoning-and-action loop.

ReAct + external stateRecover using external task state, then let the model choose the remaining actions.

Durable executionReplay recorded completed calls; return control to the agent when execution reaches unfinished work.

Plan-and-executeRetain a high-level plan while a model executor chooses concrete actions. That executor can diverge from the saved plan.

Read the metrics without losing the meaning.

Ψ · ContinuityHigher means greater continuity. For Autopilot and plan-and-execute: fraction matching the saved suffix. For online strategies: 1 − normalized suffix entropy, calculated within matching prefixes. These definitions assess different recovery contracts; they are not identical measurements.

Apost · AgreementAgreeing pairs of attempted suffixes ÷ all suffix pairs with the same prefix. Invalid and repeated attempts stay in scope. It compares recoveries with one another, not with an individual saved plan.

Dseq post · Edit distanceMean number of call insertions, deletions, or substitutions between attempted suffix pairs from the same prefix. Invalid attempts remain included. Lower means more similar, not necessarily better.

Cpath post · CoverageDistinct valid irreducible suffix paths exercised ÷ all valid irreducible Goal continuations from the actual crash resources. It measures breadth. Different prefixes can have different valid continuation universes.

Rcorr post · Strict correctnessValid, Goal-reaching executions without repeated or extraneous calls or errors ÷ all trials. The valid non-repeating count is its numerator. Failed or invalid trials remain in the denominator.

Goal completionFraction that reaches Goal. A trace can reach Goal and still repeat an operation or contain invalid actions.

E1 variation · Normalized entropyHow spread out the observed full-path choices are, normalized by the trial count. Zero means one observed path. High variation does not by itself imply low correctness.

E1 coverage & distanceCoverage counts observed valid irreducible full paths relative to the graph's feasible path universe. Distance averages call edits between attempted full sequences.

What gets weighted?

Within a model × graph × strategy condition, a supported prefix group's metric is weighted by its trial count. Agreement and distance exclude singleton groups from the pairwise estimate and show the supported trial count. Coverage retains all groups. Combined summaries give each model × graph condition equal weight.

An aggregate coverage decimal is a mean of fractions—not a single numerator divided by a pooled path universe. Correctness counts, in contrast, add directly across all trials.

What these experiments leave open

  • The graphs abstract API dependencies. They omit real payloads, business logic, authentication, and hidden server state.
  • Crashes occur at completed-call boundaries. Ambiguous in-flight commits, partitions, storage failures, and concurrent failures are outside scope.
  • Model/provider configurations and finite samples limit generalization. E2 and E3 use different model sets and prefix sampling; they are not a controlled head-to-head comparison.
  • Continuity is distinct from correctness. A preserved bad plan is still a bad plan; several different routes can all be correct.
  • Plans in these experiments require no new model reasoning after execution begins. Nested reasoning steps are future work.

Where the numbers come from

The build reads audited condition CSVs under each experiment's analysis directory and uses curated anonymized graph assets and recorded call sequences for animation. Numeric results are taken from those exports; the TeX manuscript supplies the narrative. Each build writes a source-hash manifest alongside these standalone pages.

Use “Download condition CSV” in any explorer to export all conditions for that experiment, with model and graph identities. The CSV uses milliseconds for recovery latency and seconds for E1 latency. Values are exported without display rounding.
